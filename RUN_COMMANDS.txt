================================================================================
  WHAT THIS PROJECT DOES
================================================================================

  VoltGuard validates Modbus industrial control commands against a physics
  simulation of a pipeline. Each command is checked:

    cmd value  ->  physics engine  ->  pressure & flow  ->  decision engine
                                                                   |
                                                 pressure > 12 bar  ->  DROP
                                                 flow     > 5.0     ->  DROP
                                                 both within limits  ->  ALLOW

  Results are streamed live to a professional web dashboard with:
    - KPI cards, donut chart, bar+line chart, pressure timeline
    - Filterable decision log table with CSV export
    - Live pipeline terminal with stage tracker
    - API explorer with embedded Swagger UI

================================================================================
  PHYSICS THRESHOLDS
================================================================================

  Parameter        Limit          Action if Exceeded
  ---------------- -------------- ----------------------------
  pressure_bar     > 12.0 bar     DROP  (Catastrophic Failure)
  flow_rate        > 5.0          DROP  (Catastrophic Failure)
  Both within      --             ALLOW (Safe)

  Python formula (fallback):
    pressure = 6.0 + 0.12 * cmd + 0.8 * (1.0 + 0.015 * cmd)
    flow     = 1.0 + 0.015 * cmd
    where cmd = Modbus register value

  Cmd value lookup table:
    cmd =  5  -> pressure= 7.460 bar, flow=1.075  -> ALLOW
    cmd = 12  -> pressure= 8.384 bar, flow=1.180  -> ALLOW
    cmd = 25  -> pressure=10.100 bar, flow=1.375  -> ALLOW
    cmd = 40  -> pressure=12.080 bar, flow=1.600  -> DROP
    cmd = 55  -> pressure=14.060 bar, flow=1.825  -> DROP
    cmd = 80  -> pressure=17.360 bar, flow=2.200  -> DROP

================================================================================
  BUGS FIXED (history)
================================================================================

  1. "Interceptor error:" with no message in live terminal
     Root cause: asyncio.create_subprocess_exec fails on Windows with
     SelectorEventLoop (used by uvicorn).
     Fix: Replaced with subprocess.Popen in a thread + queue.Queue to pass
     output back to the async SSE generator.

  2. UnicodeEncodeError crashing interceptor.py
     Root cause: Emoji characters (green/red circles) in print() cannot be
     encoded by Windows cp1252 codepage when subprocess stdout is captured.
     Fix: Replaced emoji with plain ASCII [ALLOW] / [DROP] in interceptor.py.
     Also set PYTHONIOENCODING=utf-8 in the subprocess environment.

  3. "Too many requests" — SSE auto-reconnect loop
     Root cause: Browser EventSource reconnects automatically when stream ends,
     causing infinite pipeline re-runs.
     Fix: Server sends "retry: 0" as the first SSE frame to disable reconnect.
     Client EventSource is explicitly closed on type=="done".

  4. simulate_pipeline.py dead Modelica branch
     Root cause: Function always returned fallback result even when Modelica
     simulation succeeded, discarding the real result.
     Fix: Now returns Modelica result when pressure_bar and flow_rate are
     present in the response dict.

  5. interceptor.py Python fallback missing numeric thresholds
     Root cause: Fallback decide() only checked state=="Catastrophic Failure",
     missing the pressure > 12 and flow > 5 numeric checks.
     Fix: Python fallback now mirrors Rust logic exactly.

================================================================================
  TROUBLESHOOTING
================================================================================

  "python is not recognized"
    Install Python 3.8+: https://www.python.org/downloads/
    Tick "Add Python to PATH" during installation.

  "ModuleNotFoundError: No module named 'fastapi'"
    Run: pip install fastapi==0.115.5 uvicorn==0.32.1

  "Address already in use" / port 8000 busy
    Use a different port:
      python -m uvicorn app:app --host 0.0.0.0 --port 8001 --reload
    Open: http://localhost:8001

  Dashboard shows "No data yet"
    Run interceptor.py first, or click Run Pipeline in the dashboard.

  Live terminal shows "Interceptor error:" (no detail)
    Fixed in current version. If it reappears, restart the server:
      Ctrl+C in server terminal, then run uvicorn command again.

  Rust binary not found (shown in console)
    Normal — Python fallback runs automatically with identical results.

  "OMPython not found" / OpenModelica not available
    Normal — Python math fallback runs automatically.
